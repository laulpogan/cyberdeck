paul-thinkpiece-pipeline (Dell and Spark) — "forge"

The oldest and largest. ~/paul-thinkpiece-pipeline, referred to elsewhere as "forge". Its README describes a fully local multi-stage pipeline:

"Everything runs on-box. No external API calls. No cloud costs."

Architecture as documented — each model a specialist:

  • Reasoning model — Qwen 3.5-122B-A10B via vLLM on 127.0.0.1:8000, doing planning, structure, factual reasoning, curation, critique, assembly
  • Voice model — the Paul fine-tune via vLLM on a second port, doing sentence-level voice transfer; "the stylist, not the writer"
  • RAG index over the published Substack archive (~200 posts)

The README's stated reason for the split:

"The fine-tuned 8B model has good voice mimicry but weak topic adherence and high hallucination rate when asked to invent… The 122B MoE model is the inverse: it can plan and reason but its prose is generic-LLM-flavored."

Eight stages: seed → research → plan → draft → stylize → assemble → critique → publish (human in the loop).

Contents include docs/ with ~20 design documents, runs/ with thinkpiece_batch_v1 through v3, eval/, dpo/, config/, and roughly thirty training logs from the base bake-off era (qlora_70b*.log, qlora_gemma31b*.log, qlora_v4*_8b.log, dpo_pipeline_27b.log).

Notable docs inside docs/: POSTING.md, POSTING_PIPELINE_HANDOFF.md, LINKEDIN_TOP_VOICE_PLAN.md, REDDIT_AUTONOMOUS.md, SUBSTACK_AUTONOMOUS.md, LATE_AUTONOMOUS.md, RESEARCH_PIPELINE.md, CONTENT_EVOLUTION_SERIES.md, DUAL_SPARK_PLAN.md, DASHBOARD.md, llm_isms_research.md, rag_citation_design.md, ECOSYSTEM_BRIEF_2026_05_31.md.

RESEARCH_PIPELINE.md (status: proposed, 2026-05-06) states the gap that later shaped the essays repo:

"V8 carries the entire load: it picks the angle, builds the argument, finds the contrarian read, and writes it in voice — all in one pass. V8 was not trained for any of that except the last step. It is a voice model. It learned to write like Paul. It did not learn to think like Paul."

our-lady-book-pipeline (Dell) + our-lady-of-champion (Dell, Mac)

Novel-drafting automation. The corpus repo our-lady-of-champion is ten markdown lore bibles — brief, engineering, glossary, handoff, known-liberties, maps, outline, pantheon, relics, secondary-characters — described by the pipeline as "read-only source-of-truth".

The novel's premise, from its brief:

"A historical fiction retelling of the Spanish conquest of the Mexica (Aztec) empire, 1519 to 1521, in a world where both civilizations wage war using gilded, bone-powered war-engines: Reliquaries on the Spanish side, Teōmecahuītlī (god-engines) on the Mexica side. The conquest proceeds along the documented timeline. The mecha do not change the outcome. They change what the outcome means."

The metaphysics is a named system — "Sanctified Death" — with three potency variables (ritualization, witness, acceptance), and the brief notes both civilizations "have, over centuries, built industrial pipelines for producing this fuel. Neither calls it that."

Pipeline design per its README: voice fidelity from a pinned fine-tune checkpoint (config/voice_pin.yaml), factual consistency from a 5-axis critic plus typed RAG (historical, metaphysics, entity-continuity, arc-position, thematic don'ts), nightly autonomous runs via openclaw, weekly digest, hard-block alerts only, and per-chapter retrospectives with an open-thesis registry.

Stale-doc flag. The README's Status section says:

"2026-04-21: Architecture locked, scaffolding committed, no code yet."

The tree disagrees. canon/ holds 24 chapters, 88,706 words; there are 27 scenes, 15 retrospectives, 6 runs, 2 theses, an ARCHITECTURE.md with ADRs, a docs/ site with _config.yml, gallery.md, index.md, per-chapter pages, and our_lady_of_champion.pdf.

CONTENT_EVOLUTION_SERIES.md (2026-05-21) describes it as shipped:

"our-lady-of-champion is COMPLETE, not in-progress. 24 chapters + ~91,204 words shipped, with downloadable PDF, per-chapter retrospectives, self-portrait pipeline diagram, Architecture + ADRs + PIPELINE.md, hero carousel, gallery, screenplay pilot adaptation. Live at loganclaw9000.github.io/our-lady-book-pipeline/."

essays (Mac) — the blog/Substack pipeline

~/Source/essays. Its README:

"Long-form essay production for the Slancha content campaign (stealth phase). Posts ship to laulpogan.substack.com ('Engineering Our Social Vehicles'), then get cut down for LinkedIn, Twitter/X, and selected subreddits."

PIPELINE.md defines a nine-stage lifecycle, each stage ending in a commit on the essay branch:

  1. BRIEF — one page; kill criterion is "if the claim can't be stated falsifiably enough to argue about, it's a vibe, not an essay"
  2. RESEARCH — fan-out agents, primary sources, every claim tagged [P/S/T, source, date, 0-100], conflicts flagged not silently resolved
  3. THESES — 4–6 deliberately divergent thesis lines worked down independently (economics, geopolitics, regulation, labor), then looked at for convergence; "where independent lines arrive at the same place, that intersection is the essay's spine"
  4. PERSONA DEBATE — "Not review — debate." Personas argue for and against across at least two rounds; for AI-economics pieces the cast is a Marxist economist, a mainstream/marginalist economist, a natsec hawk, an open-source advocate, a frontier-lab insider, a China-policy scholar. A moderator scores which arguments survived
  5. OUTLINE — locked structure
  6. DRAFT — the Substack canonical version, written to STYLE.md
  7. VOICE RINSE — the fine-tune applied paragraph-by-paragraph, N candidates at temp ~0.6, a reasoning model curating the strongest assembly; "keep BEST attempt, never latest"
  8. PLATFORM CUTS — native rewrites per platform, "not truncations"
  9. PUBLISH + LOG — Substack first as canonical URL, cuts link back, performance logged back into the essay dir after a week

The file has an explicit "learnings imported from paul-thinkpiece-pipeline (forge)" section — voice and thinking are separate problems; research-first grounding was forge's known gap ("reads like Paul, argues like a fine-tune") and this repo "fixes it structurally: stages 2-4 happen before any prose exists"; deterministic pattern audits before LLM judges, "name them honestly: pattern audits, not detectors".

DISTRIBUTION.md sets a stealth posture: author brand not company brand, no Slancha mention, and

"by the time Slancha surfaces, the author is already a known voice on AI economics, inference infrastructure, and model geopolitics."

STYLE.md is a voice dossier built from six named published posts, with a method note that WebFetch's summarizer refused verbatim reproduction so raw HTML was parsed directly. It characterizes the register as "essayistic infotainment for tech-literate millennials" and "the smart friend explaining a framework at a party", and quotes the blog's through-line: "societies are organisms… organisms are not individual species, but rafts of cooperating ones."

Four essay directories exist: aiewf-2026 (assets only), closed-source-open-season (complete lifecycle — BRIEF, RESEARCH, THESES, DEBATE, OUTLINE, DRAFT, RINSE_REPORT, GATE_REPORT, PUBLISHING, cuts, assets, references), dead-labor (through GATE_REPORT, with a DRAFT_SUPERSEDED_FUSED.md), and the-switch (BRIEF through RINSE_REPORT plus cuts). Git history shows the stage-per-commit discipline is real — twelve commits walk one essay from "Brief closed-source OpenAI incident essay" to "final title/subtitle/switch-link".

Outreach

The foundry — digital employees (slancha-business/foundry)

Described as "a reusable system to mint, run, govern, and grow digital employees that drive Slancha's growth." An employee is a Claude Code subagent file with a mandate, tool bundle, output contract, fact-gate, escalation rules, tier, and self-documentation. Minting one is copying EMPLOYEE_TEMPLATE.md and running ./install.sh.

Roster in agents/ (each with a paired .task.md): accelerator, aeo, coach, concierge, cos, counsel, creator-scout, herald, hunter, ledger, prospector, and more under sibling directories — scout, scribe, smith, strategist, support, theorist, warden, reviewer, monitor.

The four hard rules as written:

  1. "Everyone starts at tier intern = draft-only. Humans send every external touch."
  2. Fact-gate before any draft is surfaced — "paul-voice fabricates bios at temp >0.6 — never auto-send."
  3. Always-escalate for Tier-1 logos/investors, any positive or angry reply, pricing/contract/legal, fundraise commitments, public statements.
  4. "Recall before acting" — grep the Soul vault first; avoid collision with anyone the founder is already working.

The README draws a distinction: "recon is the shared toolbox" (deterministic CLI verbs over a SQLite DB plus a web UI) and "foundry agents are the operators".

ATLAS.md documents a five-stage learning loop — CAPTURE (runtime → decisions/*.jsonl) → MEASURE (scorecard, HR report) → REFLECT (coach, weekly → LESSONS.md) → IMPROVE (smith, weekly → skills library) → APPLY (human) → VERIFY (scorecard trend) — explicitly "modeled on the dotfiles-claude Soul three-loop".

The autonomy layer

forge_autonomous (~/finetuning/forge_autonomous, Dell)

A systemd daemon, deliberately not cron:

"Operator directive 2026-06-01: constant GPU uptime — always running OR evaluating an experiment, full auto; operator decisions queue, never block; branching realities → investigate both; maximize spark GPU; never stop."

Loop: pull highest-priority pending experiment from queue.jsonl; if it is a training job, stop serving first ("HARD RULE: never co-run train+serve") and run a fuser/memory preflight; execute under "eagle-watch" with 3-second GPU snapshots; record; enqueue branches; append operator-decision items to decisions.jsonl and continue rather than block; if the queue empties, enqueue a keep-busy eval so the GPU never idles.

Its directory also holds corpus builders for the outreach line (build_outreach_corpus.py, build_outreach_full.py), build_enriched_sft.py, capability_ladder.py, cost_quality.py, difficulty_select.patch, and champions.json.
