dell ran 12 concurrent sequences against a max-num-seqs of 32 — KV cache was 98.2% full with 56 requests queued and 804 preemptions, so admitted work was being evicted and recomputed. Raising --gpu-memory-utilization from 0.75 to 0.86 took KV blocks from 845 to 1063 and concurrency from 12 to 32, with preemptions at 2. --kv-cache-dtype fp8 would have been the bigger win on paper and is a documented dead end on sm_120: no FLASH_ATTN path, so vLLM silently falls back to FlashInfer, whose vendored CCCL rejects this nvcc pairing — and it fails after /health already returns 200.

Orin ran 8 slots at 16,384 tokens each — below hermes' 64,000 minimum, so every card it took failed instantly. Dropping to -np 2 gave 65,536 per slot and it started delivering.

Tonight's fixes

All of these were the same class of bug: a plausible proxy standing in for the thing it was meant to measure.

meta-floor was reverting bin/ because recovery was workingThe floor under self-modification decided the recovery path was broken by grepping self-heal's own stdout for traceback|command not found|syntax error|no such file — but printing those strings while reporting a broken worker is exactly what self-heal does. At 3 hits it ran git checkout $last -- bin/, reverting every daemon in the fleet. 94 cards, 85 unresolved, effectively all self-heal(3errs). This is also why hand-applied fixes kept vanishing from disk minutes after landing, and why block --reason came back after being fixed. Now counts only failures systemd reports about the unit.root cause
82 phantom cards closedTriaged by body: 83 carried only the (Nerrs) signal with no real defect; 2 were genuine and left open for the fleet. Board ready went 88 → 6, done 264 → 346.cleared
self-heal liveness → log mtimeWas pgrep -f "task $id". 63 worker logs were being written inside 10 minutes while pgrep found zero processes — so self-heal reclaimed live workers, stripping the assignee off one card 4 times in an hour while its log grew past 80KB. Now: a log touched inside 15 min means the worker is working.fixed
block reason is positionalblock --reason exits 2 with a usage dump, swallowed by >/dev/null at all three call sites. So the "stop after 3 reclaims" cutoff never fired and the reclaim loop had no exit. Failure is now audible.fixed
HUD boot crash, 161 restartsA commit declared skins/v2/reference.py and lint.py in the package surface without shipping either. Dangling imports killed the server at boot. Imports removed; self-heal now re-probes after restart and cards the outage with the traceback.fixed
board DB corruption, 4 eventsSwapping a WAL-mode SQLite file while processes hold it open corrupts the replacement. db-medic now REINDEXes in place, refuses to replace a DB passing integrity_check, and prunes quarantines to the newest 3 (they had reached 25GB). Final repair with zero open handles: 867/867 rows recovered.fixed
metacog single-flight guardKeyed on created_by instead of assignee, so 10 writers ran concurrently under a one-writer lock.fixed
Orin slot geometry8 slots at 16,384 tokens, below hermes' 64,000 floor — every card failed on admission. -np 2 gives 65,536 per slot.fixed
hive/ branch conflicts never cardedThe conflict-carding loop only walked refs/heads/wt. 34 commits sat stranded on hive/ branches with nothing filed.fixed
a merge that would have deleted 136 daemonsAn old hive/hand branch was mid-merge into main with 27 unmerged paths, its incoming side deleting nearly all of bin/. The 5-minute auto-commit daemon concluded it with git add -A, which staged the on-disk files and so kept all 138. Correct outcome, reached by luck. Worth a guard.survived
Langfuse wired to the fleetIt was never "receiving nothing" — 41,176 traces were already there, and LiteLLM had carried success_callback: ["langfuse"] with keys in its own .env all along. The real gap was that nothing routed through LiteLLM: all 51 hermes profiles pointed straight at :8011/:8899/:8014, so the one path with the callback was the one path nobody used. bee5–8 now route via :4000 under a fleet-worker alias, and a probe on bee5's real config landed trace 015f8a5a.wired
dell concurrency 12 → 32util 0.75 → 0.86. KV blocks 845 → 1063, queue 56 → 10, preemptions 804 → 2. 0.92 was asked for and does not fit: the co-resident services (chatterbox, xtts, ltx, sunshine) hold 8,154 MiB, and 0.92 would have overcommitted the card.fixed
merge guard on the auto-commit daemonThe daemon that concluded today's dangerous merge now refuses while MERGE_HEAD, a rebase, or unmerged index entries exist, leaving conflicts to auto-merge and meta-merge, which abort and card them. Proven on a modify-vs-delete conflict. Separately, memory-sync.sh guarded with [ -d .git/MERGE_HEAD ] — MERGE_HEAD is a file, so that test had never once fired.fixed
swallowed CLI failures now card themselvesThe reclaim spiral survived because a daemon's argparse rejection went into /dev/null, and a human reading the journal is what found it. cli_failure_card.py reads the journal instead, attributes each rejection to the emitting unit, and files one card per unit per hour. It caught two defects in itself during testing — including printing the very signature it greps for, which made it card self-heal every 60s.fixed

Every root cause found today was a proxy. Each one was a plausible stand-in for the thing it claimed to measure, and each was wrong in the same direction — confidently reporting a state that was not the case. Liveness read process presence where it needed log mtime. Daemon health read the daemon's own stdout where it needed systemd's exit status. Merge safety read nothing where it needed MERGE_HEAD. CLI success read nothing, because the exit code went to /dev/null.
